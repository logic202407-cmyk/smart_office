## 4. 引言段落完整初稿

### 4.1 第一段：背景与问题

随着开放式办公环境的普及和移动办公设备的广泛应用，屏幕偷窥（shoulder surfing / visual hacking）已成为组织信息安全管理中不可忽视的威胁。据统计，Verizon 2024 年数据泄露调查报告指出，约 12% 的安全事件涉及物理层面的信息窃取，其中屏幕偷窥是最常见的手段之一。在金融、医疗、政务等高度敏感的工作场景中，员工屏幕上的机密信息被他人近距离窥视可能造成严重的泄密后果。传统的防偷窥手段包括物理防窥膜（限制可视角度）、基于摄像头的监控系统（人工或 AI 识别可疑行为）、以及红外线（PIR）接近传感器等。然而，这些方案均存在固有缺陷：物理防窥膜影响正常显示亮度、降低用户体验；摄像头方案虽能实现视觉检测，但本身即为一种"监控"，在办公环境中可能引发二次隐私争议；PIR 传感器仅能检测运动目标，对于静止站立窥视者完全失效，且检测精度低、环境适应性差。

### 4.2 第二段：毫米波雷达的优势

毫米波雷达技术为上述问题提供了一种非视觉、隐私友好的人体感知解决方案。与摄像头不同，毫米波雷达通过发射 24GHz 或 60GHz 频段的调频连续波（FMCW）信号检测目标的距离、速度和方位信息，不采集任何视觉图像数据，从根本上避免了隐私泄露的风险。更重要的是，现代毫米波雷达传感器能够检测运动目标和静止目标——这是 PIR 等被动红外传感器不可比拟的核心优势。当前毫米波雷达在智能家居、自动驾驶、工业测距等领域已得到广泛应用，在办公隐私保护这一新兴场景中具有巨大的应用潜力。

### 4.3 第三段：相关工作

（简述现有相关研究，指出空白）

近年来，已有研究者探索了毫米波雷达在人体感知领域的应用。文献[1]基于 60GHz 雷达实现了厘米级人体定位，文献[2]利用 FMCW 雷达进行生命体征检测，文献[3]提出了基于 WiFi CSI（信道状态信息）的人体行为识别方法。但上述工作主要关注定位精度或健康监测，尚未针对办公场景中的防偷窥需求设计专用系统。文献[4]提出了基于 PIR 传感器阵列的人员接近检测，但无法区分静止与运动的偷窥行为。本文针对这一空白，设计并实现了一套基于 LD2410B 24GHz 毫米波雷达的非视觉防偷窥人体感知系统。

### 4.4 第四段：本文贡献

本文的主要贡献如下：

1. **提出了一种基于毫米波雷达的非视觉防偷窥方案**：以 HLK-LD2410B 24GHz 雷达为核心传感器，取代传统的摄像头或 PIR 方案，既能检测运动人体又能检测静止人体，从根本上避免二次隐私泄露。
2. **设计了距离-停留时间双重判定的防偷窥状态机**：通过雷达上报的目标距离和能量信息，结合目标在近距离区域的停留时间，实现对偷窥行为的自动判定与分级响应（从提醒到告警到隐私保护）。
3. **实现了多模态交互机制**：本地 OLED 屏幕实时显示安全状态，USB CDC 串口与 PC 端联动（支持屏幕遮罩/锁屏/告警弹窗等保护动作），PAJ7620U2 手势传感器支持零接触交互控制。
4. **完成了完整的嵌入式系统实现与实验验证**：在 ESP32-S3 平台上完成了固件开发，开展了 6 组定量实验评估系统的距离精度、静止检测能力、防偷窥判定正确率、抗干扰能力和响应性能。

## 5. 系统总体设计框图文字描述

### 5.1 系统分层架构

系统采用**四层体系结构**，按从下到上的顺序分为硬件层、驱动/协议层、服务层和应用层：

**硬件层**包含四个核心器件：
- ESP32-S3 双核 240MHz 微控制器（主控芯片）
- HLK-LD2410B 24GHz 毫米波雷达模块（人体感知传感器）
- PAJ7620U2 手势识别传感器（无接触交互输入）
- HS96L03W2C03 SSD1306 OLED 128×64 屏幕（本地状态显示）

**驱动/协议层**包含四个驱动模块：
- LD2410B UART 协议解析引擎（处理雷达上报帧与配置帧）
- PAJ7620U2 I2C 驱动与手势识别（读取手势寄存器，映射为手势事件）
- SSD1306 OLED I2C 驱动（负责屏幕绘制与 UI 渲染）
- USB CDC 串口协议封装（实现 JSON 序列化/反序列化）

**服务层**包含系统运行的核心服务：
- 状态管理（维护系统工作状态）
- 事件分发（接收雷达事件、手势事件、PC 命令，分发给状态机）
- LED/蜂鸣器控制（状态指示与告警输出）
- 数据缓存与日志（运行数据记录与调试日志输出）

**应用层**实现业务逻辑：
- 防偷窥状态机（六状态判定逻辑）
- 手势交互逻辑（8 种手势 → 8 种系统操作映射）
- OLED UI 渲染引擎（6 种状态界面模板）
- PC 通信服务（状态上报与命令处理）

### 5.2 数据流路径

系统包含三条主要数据流路径：

**路径 A（感知-反馈主路径，周期 ~100ms）**：
```
LD2410B → UART上报帧 → RadarDriver解析 → RadarData
  → StateMachine.inject_radar_data()
  → 状态转换决策
    → OledDriver.show_*()           [更新本地显示]
    → PcCommHandler.send_state()    [上报PC端]
    → GPIO 更新 LED/蜂鸣器          [硬件指示]
```

**路径 B（手势交互路径，事件驱动）**：
```
PAJ7620U2 → I2C中断 → GestureDriver读取寄存器
  → GestureType 枚举值
  → StateMachine.inject_gesture()
  → 对应操作（亮度调节/切换界面/手动触发隐私保护等）
  → PcCommHandler.send_event("gesture_detected", "UP")
```

**路径 C（PC 控制路径，事件驱动）**：
```
PC → USB CDC → PcCommHandler 接收 JSON 字符串
  → ArduinoJson 解析
  → PcCommand 分发
    → set_threshold: 更新阈值参数
    → set_state: 强制状态跳转
    → radar_config: 配置雷达参数
    → reset: 系统复位
  → 回复 response 确认
```

### 5.3 系统边界与接口

| 接口方向 | 输入 | 输出 | 通信方式 |
|---------|------|------|---------|
| 雷达→ESP32 | LD2410B 目标上报帧 | 解析后的 radar_data | UART 256000bps |
| 手势→ESP32 | PAJ7620U2 手势编号 | GestureType 枚举 | I2C 400kHz, 中断触发 |
| ESP32→OLED | 屏幕缓冲区 | 128×64 像素显示 | I2C 400kHz |
| ESP32↔PC | USB CDC JSON 命令 | USB CDC JSON 数据 | USB CDC (虚拟串口) |
| ESP32→用户 | — | LED 状态指示、蜂鸣器告警 | GPIO |

## 6. 硬件设计章节关键内容

### 6.1 主控芯片选型：ESP32-S3

**选型理由（论文中需阐述的要点）**：

1. **双核 LX7 处理器**：240MHz 主频，足够同时处理雷达数据解析（~10Hz）、OLED 刷新（~10Hz）、PC 通信和手势检测。
2. **原生 USB OTG**：支持 USB CDC 虚拟串口，无需外部 USB-UART 桥接芯片（如 CP2102、CH340），降低 BOM 成本。
3. **丰富外设接口**：3 个 UART（1 个给雷达，1 个调试）、2 个 I2C 控制器（OLED 与手势共用一条 I2C 总线）、20+ GPIO。
4. **成熟开发生态**：Arduino-ESP32 框架 + PlatformIO 工具链，开发效率高，社区库丰富（U8g2、Adafruit SSD1306、PAJ7620U2 驱动）。
5. **性价比**：批量价约 ¥20-30，适合低成本隐私保护终端。

### 6.2 人体感知传感器选型：HLK-LD2410B

**选型理由（论文核心亮点）**：

1. **静止人体检测能力**：这是区别于传统 PIR 传感器的最关键特性。LD2410B 采用 24GHz FMCW 技术，可实时上报运动目标距离（moving_distance）和静止目标距离（static_distance）两个独立字段。PIR 传感器仅能检测红外辐射变化，当窥视者保持静止时 PIR 完全失效。
2. **非视觉特性**：仅输出距离和能量数值，不采集任何图像信息，从根本上避免二次隐私泄露。
3. **厘米级精度**：距离上报精度可达 1cm（论文实验中将验证），满足防偷窥场景的分级距离判定需求（150cm 接近、80cm 疑似）。
4. **易集成性**：UART 接口（256000bps 默认），通信协议公开，MCU 端仅需实现字节级状态机解析器即可接入。
5. **低成本**：模块价格约 ¥30，相比 60GHz 雷达方案（如 IWR6843，¥300+）具有显著成本优势。

**与其他方案的对比（论文建议表格）**：

| 特性 | LD2410B 毫米波雷达 | PIR 热释电红外 | 摄像头视觉方案 |
|------|-------------------|---------------|--------------|
| 静止检测 | ✅ 支持 | ❌ 不支持 | ✅ 支持 |
| 隐私保护 | ✅ 非视觉 | ✅ 非视觉 | ❌ 有隐私争议 |
| 距离精度 | ~1cm | 模糊（有无判断） | 像素级（需标定） |
| 光照敏感 | 不敏感 | 受温度影响 | 受光照影响 |
| 成本（参考） | ¥30 | ¥3-5 | ¥50-200（含摄像头模组） |
| 功耗 | ~90mA | ~1mA | ~200+mA |
| 可穿透性 | ✅ 可穿透非金属 | ❌ | ❌ |

### 6.3 手势传感器选型：PAJ7620U2

**选型理由**：

1. **9 种手势识别**：上、下、左、右、前、后、顺时针、逆时针、波浪，覆盖系统交互所需的所有操作。
2. **I2C 接口**：与 OLED 共用 I2C 总线（地址 0x73，与 OLED 0x3C 不冲突），不额外占用 MCU 引脚。
3. **中断输出**：有手势时 INT 引脚拉低，MCU 可通过外部中断或轮询读取，无需频繁查询 I2C 寄存器。
4. **低功耗**：工作电流约 10mA，睡眠模式更低。
5. **低成本**：模块价格约 ¥8-10。

### 6.4 OLED 屏幕选型：HS96L03W2C03 (SSD1306)

**选型理由**：

1. **I2C 接口**：与手势传感器共用总线，连线简洁（仅 SCL/SDA 两根线）。
2. **128×64 分辨率**：足以显示中文状态文字、距离数字、能量柱状图和图标。
3. **低功耗**：典型功耗约 20mA，支持软件调亮度。
4. **U8g2 库支持**：完善的 UTF-8 中文显示支持（文泉驿字体），可显示"安全"、"警告"、"隐私保护"等中文文字。
5. **低成本**：模块价格约 ¥6-8。

### 7.2 防偷窥状态机（论文核心创新点）

#### 7.2.1 六状态定义

| 状态编号 | 状态名 | 含义 | 触发条件 |
|---------|-------|------|---------|
| S0 | NORMAL | 正常/无人 | 雷达无目标或距离 > 阈值 |
| S1 | HUMAN_DETECTED | 检测到人 | 雷达检测到目标且距离 > NEAR_DIST (150cm) |
| S2 | APPROACHING | 正在接近 | 雷达检测到目标且 NEAR_DIST > 距离 > VERY_NEAR_DIST (80cm) |
| S3 | SUSPECTED_PEEPING | 疑似偷窥 | 距离 < VERY_NEAR_DIST (80cm) 并持续 SUSPECT_TIME (3s) |
| S4 | PRIVACY_PROTECT | 隐私保护已触发 | 疑似超时 OR 手势确认；触发 PC 端遮罩/锁屏等动作 |
| S5 | ALARM | 告警 | 隐私保护中目标仍未远离；触发蜂鸣器/闪光 |

#### 7.2.2 状态转换逻辑（论文建议用表格呈现）

| 当前状态 | 事件/条件 | 下一状态 | 执行动作 |
|---------|----------|---------|---------|
| NORMAL | 目标进入 (有 target, dist > 150cm) | HUMAN_DETECTED | OLED 显示"⚠ 检测到人 Nm"；上报 PC |
| NORMAL | 目标极近 (dist < 80cm) | SUSPECTED_PEEPING | 直接跳转（人突然近距离出现） |
| HUMAN_DETECTED | 目标接近 (dist < 150cm) | APPROACHING | OLED 显示"⚠ 有人接近"；上报 PC |
| HUMAN_DETECTED | 目标离开 (无目标 > 2s) | NORMAL | 恢复安全显示 |
| APPROACHING | 目标继续接近 (dist < 80cm) | SUSPECTED_PEEPING | 开始 3s 倒计时；OLED 闪烁 |
| APPROACHING | 目标后退 (dist > 150cm) | HUMAN_DETECTED | 状态回退 |
| APPROACHING | 目标离开 (> 2s) | NORMAL | 恢复 |
| SUSPECTED_PEEPING | 持续 < 80cm 达 3s | PRIVACY_PROTECT | 触发隐私保护；OLED 显示"🔒 隐私保护中" |
| SUSPECTED_PEEPING | 目标后退 (dist > 80cm) | APPROACHING | 解除嫌疑 |
| SUSPECTED_PEEPING | 目标离开 | NORMAL | 解除 |
| SUSPECTED_PEEPING | 手势顺时针确认 | PRIVACY_PROTECT | 手动触发保护 |
| PRIVACY_PROTECT | 冷却时间到 (60s) | NORMAL | 自动恢复 |
| PRIVACY_PROTECT | 手势逆时针解除 | NORMAL | 手动恢复 |
| PRIVACY_PROTECT | 目标仍在且告警时间到 | ALARM | 升级告警 |
| ALARM | 告警时间到 (8s) | NORMAL | 蜂鸣器停、系统恢复 |
| ALARM | 目标离开 | NORMAL | 自动解除 |

#### 7.2.3 距离判定策略

系统使用**保守距离策略**：当雷达同时上报运动目标和静止目标时，取两者中距离更近的值作为判定依据。即：

```
effective_distance = min(moving_distance, static_distance)
```

这样做是为了在运动目标接近时（moving_distance 递减）或静止目标站立时（static_distance 恒定）均能及时触发防偷窥逻辑。

### 7.3 LD2410B 协议解析

#### 7.3.1 帧结构

LD2410B 使用两种帧格式：

**上报数据帧（雷达→MCU，主动推送，~100ms 间隔）**：

```
帧头:     F4 F3 F2 F1        (4B)
长度:     Length (LE)         (2B) — 后续数据长度
类型:     DataType            (1B) — 0x01=工程模式, 0x02=基本信息
固定:     AA                  (1B)
目标数据: target_state      (1B) — 0x00=无人, 0x01=运动, 0x02=静止, 0x03=两者
          moving_distance   (2B LE) — 运动目标距离 (cm)
          moving_energy     (1B) — 0-100
          static_distance   (2B LE) — 静止目标距离 (cm)
          static_energy     (1B) — 0-100
          detect_distance   (2B LE) — 感应距离 (cm)
分隔:     55                  (1B)
校验和:   Check               (1B) — 从 F4 到 55 累加和取低 8 位
帧尾:     F8 F7 F6 F5        (4B)
```

**配置命令帧（MCU→雷达，请求-应答模式）**：

```
帧头:     FC FB FA FD        (4B)
长度:     Length (LE)         (2B)
命令字:   Cmd (LE)            (2B)
参数:     Value               (N B)
帧尾:     04 03 02 01        (4B)
```

#### 7.3.2 字节级状态机解析器

论文中需重点描述的关键软件设计：采用**字节级有限状态机解析器**处理雷达数据流，以解决 UART 通信中的粘包、半包和错帧问题。

**状态机状态定义**：

```
WAIT_HEAD_0 → WAIT_HEAD_1 → WAIT_HEAD_2 → WAIT_HEAD_3 → WAIT_LENGTH_L
  → WAIT_LENGTH_H → WAIT_PAYLOAD → WAIT_TAIL_0..4 → FRAME_COMPLETE
```

**关键特性**：
- **粘包处理**：一帧解析完成后（FRAME_COMPLETE），状态机自动复位到 WAIT_HEAD_0，继续解析剩余的字节。
- **半包超时**：50ms 无新字节到达时自动复位，丢弃不完整帧。
- **校验验证**：使用 LD2410B 专用校验和算法验证数据完整性。
- **错误恢复**：任意状态匹配失败均回到 WAIT_HEAD_0，丢弃已积累的无效字节。

#### 7.3.3 能量滤波

论文中可阐述一阶低通 IIR 滤波算法处理能量值抖动：

```c
filtered = filtered × (1 - α) + raw × α
```

其中 α = 0.3（滤波系数，可根据实验调优）。

### 7.4 PC 联动通信协议

#### 7.4.1 物理层

- **接口**：USB CDC（虚拟串口）
- **速率**：由 USB 2.0 Full Speed 决定（实际约 1MB/s，远高于串口协议需要）
- **编码**：UTF-8 JSON
- **分隔符**：`\n`（每行一条独立消息）

#### 7.4.2 上行协议（ESP32 → PC）

| 类型 | 触发条件 | 频率 | JSON 示例 |
|------|---------|------|----------|
| state_report | 状态变化或周期上报 | ~5Hz | `{"type":"state_report","data":{"state":"APPROACHING","distance_cm":95,...}}` |
| event | 事件触发（手势、告警） | 事件驱动 | `{"type":"event","data":{"event":"gesture_detected","detail":"UP"}}` |
| heartbeat | 定时 | 5s 一次 | `{"type":"heartbeat","data":{"uptime_ms":1234567,"state":"NORMAL"}}` |
| log | 调试/系统消息 | 按需 | `{"type":"log","data":{"level":"INFO","message":"Radar initialized"}}` |

#### 7.4.3 下行协议（PC → ESP32）

| 命令 | 功能 | JSON 示例 |
|------|------|----------|
| set_threshold | 更新距离/时间阈值 | `{"type":"command","data":{"cmd":"set_threshold","params":{"near_dist_cm":150,...}}}` |
| set_state | 强制状态跳转 | `{"type":"command","data":{"cmd":"set_state","params":{"state":"NORMAL"}}}` |
| radar_config | 雷达参数配置 | `{"type":"command","data":{"cmd":"radar_config","params":{"baudrate":256000}}}` |
| get_status | 查询当前状态 | `{"type":"command","data":{"cmd":"get_status","params":{}}}` |
| reset | 系统复位 | `{"type":"command","data":{"cmd":"reset","params":{}}}` |

### 7.5 手势交互映射

| 手势 | 状态限定 | 系统动作 |
|------|---------|---------|
| 向上 (UP) | NORMAL / HUMAN_DETECTED | OLED 亮度 +1 |

| 向前 (FORWARD) | 任何 | 开启/关闭 PC 端摄像头遮挡 |

### 8.2 实验一组：距离检测精度测试

**目的**：验证 LD2410B 在不同距离下的测距精度。

**方案**：
1. 测试人员站在雷达前方 0.5m、1.0m、1.5m、2.0m、2.5m、3.0m、4.0m、5.0m 处。
2. 每个距离测试人员分别保持静止和小幅挥手（运动）两种状态。
3. 每个位置采集 100 个雷达上报帧，记录 moving_distance 和 static_distance。
4. 以激光测距仪读数为真实值，计算平均误差和标准差。

**预期数据表格**：

| 实际距离(cm) | 静止检测均值(cm) | 静止误差(cm) | 运动检测均值(cm) | 运动误差(cm) | PIR 检测 |
|-------------|-----------------|-------------|-----------------|-------------|---------|
| 50 | — | — | — | — | ✅ |
| 100 | — | — | — | — | ✅ |
| 150 | — | — | — | — | ✅ |
| 200 | — | — | — | — | ✅/❌（边缘） |
| 300 | — | — | — | — | ❌ |
| 400 | — | — | — | — | ❌ |
| 500 | — | — | — | — | ❌ |

**预期结果**：LD2410B 在 0.5-3m 范围内测距误差 < 10cm，5m 处误差 < 30cm。PIR 在 2m 以外检测不稳定。

### 8.3 实验二组：静止人体检测测试

**目的**：验证 LD2410B 对静止人体的检测能力，与 PIR 传感器对比。

**方案**：
1. 测试人员进入检测区（距雷达 1.5m），保持静止不动。
2. 记录 LD2410B 上报的 target_state 字段（0x02=静止）和 PIR 输出。
3. 持续 60 秒，记录 LD2410B 保持"静止检测"的时间比例，以及 PIR 从触发到恢复无人的时间。
4. 分别在 1m、2m、3m 距离重复测试，每个距离测试 5 次。

**预期数据表格**：

| 距离 | LD2410B 静止检测持续率 | PIR 有效检测时间 | 说明 |
|------|----------------------|-----------------|------|
| 1m | >95% | <5s | PIR 很快恢复无目标 |
| 2m | >90% | <5s | 同上 |
| 3m | >85% | 0s | PIR 完全失效 |

**预期结果**：LD2410B 在 3m 范围内静止人体检测持续率 > 85%，而 PIR 在人体静止后 3-5 秒内即恢复无目标状态，验证了 LD2410B 在静止检测方面的核心优势。

### 8.4 实验三组：防偷窥判定测试

**目的**：验证防偷窥状态机在不同接近行为下的判定正确率。

**方案**：
1. **正常经过场景**：测试人员从 4m 外以正常步速走过检测区（不靠近屏幕），记录系统是否误触发窃听判定。
2. **缓慢接近场景**：测试人员从 4m 外缓慢走到距离屏幕 50cm 处停留 5s，记录状态转移过程是否符合预期。
3. **快速接近场景**：测试人员从 4m 外快步走到距离屏幕 50cm 处，记录响应时间。
4. 每个场景测试 20 次，统计**正确率**和**响应时间**。

**预期数据表格**：

| 场景 | 测试次数 | 正确触发次数 | 正确率 | 平均响应时间 |
|------|---------|-------------|--------|------------|
| 正常经过（不触发） | 20 | 18+ | >90% | N/A |
| 缓慢接近（触发保护） | 20 | 19+ | >95% | <5s |
| 快速接近（触发保护） | 20 | 18+ | >90% | <3s |

**预期结果**：系统在缓慢接近场景中正确率最高（>95%），正常经过场景误触发率 < 10%。

### 8.5 实验四组：误触发抗干扰测试

**目的**：验证系统在办公环境常见干扰下的误触发率。

**方案**：
1. **人员走动干扰**：2 人在 3-5m 外正常行走/交谈，持续 5 分钟。
2. **机械运动干扰**：在 2m 外放置风扇（强档），运行 5 分钟。
3. **环境遮挡干扰**：测试人员持书本/文件夹遮挡身体靠近雷达。
4. **多人场景干扰**：2 人在 2-3m 处交谈，1 人靠近检测区。
5. 每个干扰场景记录系统误触发次数。

**预期数据表格**：

| 干扰类型 | 测试时长 | 误触发次数 | 误触发率 | 备注 |
|---------|---------|-----------|---------|------|
| 人员走动 | 5min | — | <5% | — |
| 风扇/机械运动 | 5min | — | <5% | — |
| 遮挡靠近 | 10 次 | — | <20% | 可能因遮挡削弱信号 |
| 多人交谈 | 5min | — | <10% | — |

**预期结果**：机械类干扰（风扇）对毫米波雷达影响较小，误触发率 < 5%；遮挡场景可能因目标信号减弱导致漏报而非误报。

### 8.6 实验五组：PC 联动响应测试

**目的**：验证 PC 端联动响应延迟和可靠性。

**方案**：
1. ESP32 通过 USB CDC 连接 PC，PC 端运行接收程序。
2. 触发隐私保护状态（S3→S4），记录从状态触达到 PC 端收到 JSON 通知的时间延迟。
3. 发送 5 条 set_threshold 配置命令，记录从 PC 发送到 ESP32 收到并执行完成的时间。
4. 每个测试重复 20 次。

**预期数据表格**：

| 测试项 | 平均延迟 | 最大延迟 | 成功率 |
|-------|---------|---------|-------|
| ESP32→PC 状态上报 | <50ms | <100ms | 100% |
| PC→ESP32 命令执行 | <30ms | <80ms | 100% |
| 连续心跳 (5s) | 标准偏差 <10ms | — | 100% |

**预期结果**：USB CDC 通信延迟在 50ms 以内，满足实时性要求。

### 8.7 实验六组：手势识别测试

**目的**：验证 PAJ7620U2 手势识别的准确率。

**方案**：
1. 测试人员在传感器前方 10-20cm 处执行 6 种手势（上、下、左、右、顺时针、逆时针）。
2. 每种手势执行 20 次，记录系统正确识别的次数。
3. 测试距离分别为 10cm、15cm、20cm。

**预期数据表格**：

| 手势类型 | 10cm 准确率 | 15cm 准确率 | 20cm 准确率 | 平均 |
|---------|------------|------------|------------|------|

## 11. 论文创新点提炼

### 创新点一：基于毫米波雷达的非视觉防偷窥方案

**核心**：选用 HLK-LD2410B 24GHz 毫米波雷达替代摄像头或 PIR 传感器作为人体接近感知的核心传感器。

**创新性**：
- 相比摄像头方案：不采集任何图像数据，从根本上避免二次隐私泄露
- 相比 PIR 方案：可检测静止人体（LD2410B 同时上报 moving_distance 和 static_distance）
- 相比传统物理防窥膜：不影响屏幕显示质量，用户体验更好

**论文中如何体现**：
- 硬件选型对比表（LD2410B vs PIR vs 摄像头）
- 实验二组定量验证静止人体检测能力（LD2410B > 85% vs PIR ≈ 0%）

### 创新点二：距离-停留时间双重防偷窥判定机制

**核心**：设计了一个六状态有限状态机，结合雷达上报的实时距离信息和目标在近距离区域的停留时间，实现对偷窥行为的精确判定与分级响应。

**创新性**：
- 传统近接检测仅为单一阈值（有人/无人），无法区分"路过"和"窥视"
- 本方案使用两个距离阈值（150cm 接近、80cm 疑似）结合停留时间阈值（3s 停留触发保护），可智能区分正常经过和疑似偷窥
- 从提醒（HUMAN_DETECTED）→警告（APPROACHING）→疑似（SUSPECTED_PEEPING）→保护（PRIVACY_PROTECT）→告警（ALARM）的五级递进响应

**论文中如何体现**：
- 状态机详细定义和转换表（第 4.2 节）
- 实验三组验证判定正确率（>90%）
- 实验四组验证误触发率（<10%）

### 创新点三：多模态交互与反馈架构

**核心**：实现了 OLED 本地显示 + PC 端联动 + 手势无接触控制的三重交互机制。

**创新性**：
- **本地 OLED**：实时显示安全状态、距离信息和图标，用户无需查看 PC 即可了解周边安全状况
- **PC 端联动**：通过 USB CDC 传输 JSON 协议，PC 端可接收状态并执行屏幕遮罩/锁屏/告警弹窗等保护动作
- **手势无接触控制**：PAJ7620U2 支持 8 种手势识别，用户可在不接触设备的情况下调节亮度、确认保护、解除告警

**论文中如何体现**：
- PC 通信协议设计（第 4.4 节）
- 手势交互映射表
- 实验五组验证 PC 联动延迟（<50ms）
- 实验六组验证手势识别准确率（>80%）

### 创新点四：完整的低功耗嵌入式实现

**核心**：在 ESP32-S3 平台上实现了完整的系统软硬件集成，包括高速 UART 协议解析（256000bps）、字节级状态机帧解析器、非阻塞 OLED 刷新、以及稳定的 USB CDC 通信。

**创新性**：
- 解决了 LD2410B 256000bps 高速 UART 下的粘包/半包/校验问题
- 字节级状态机解析器具有错误弹性（任意状态可恢复），适合长时间稳定运行
- 在 Arduino-ESP32 框架中混合调用 ESP-IDF 原生 UART DMA 驱动，兼顾开发效率和通信可靠性

**论文中如何体现**：
- 协议解析状态机设计（第 4.3 节）
- 系统模块化软件架构（第 4.1 节）
- 供电设计与功耗分析（第 3.6 节）
